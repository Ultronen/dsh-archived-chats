# 归档管理用户指南

1.6.0 停止新增回收和自动清理，旧数据保留。详情见[升级、旧数据与降级](#升级旧数据与降级)。

[English](USER_GUIDE.md) · 简体中文 · [返回 README](../README.zh-CN.md)

归档管理为 DSH 已归档聊天提供查看和管理页面，并扩展按工作区批量归档。本文对应 1.6.0，支持 DSH `0.2.1-rc.2` 并保留旧版支持；原生集成测试覆盖新旧两套锁定宿主。版本变更见[更新日志](../CHANGELOG.md)，接口和数据格式见[架构说明](ARCHITECTURE.md)。

## 会话状态与旧数据

| 位置 | 用途 | 如何返回主页面 |
| --- | --- | --- |
| 主页面会话区 | 日常继续聊天 | 已在主页面 |
| 已归档 | 保留聊天，但不在主页面会话区显示 | 点击「取消归档」 |
| 旧回收站 | 处理旧版已保存记录，不再接收新回收 | 先「恢复」到已归档，再「取消归档」 |

归档不等于删除，也不创建历史版本。旧版回收记录保留原会话文件和保护快照；当前不再提供移入操作。永久删除不可恢复，不是移入回收站。

## 安装与打开

在 DSH 插件市场搜索 `dsh-archived-chats`，核对作者为 **Ultronen** 后点击「安装」。安装完成后按宿主提示重启 DSH，打开 **设置 → 归档管理**。

也可以在运行 DSH 的主机上使用命令行安装。以下以 `web` profile 为例，请替换为实际运行 DSH 的 profile；更新和卸载也使用同一 profile：

```sh
dsh plugin --profile web add dsh-archived-chats@latest
```

若安装报错 `ERR_PNPM_ADDING_TO_ROOT`，说明该 profile 是 pnpm workspace 根目录。请加上 `-w` 重试，并替换为实际 profile：

```sh
dsh plugin --profile web add -w dsh-archived-chats@latest
```

重启 DSH，打开 **设置 → 归档管理**。主页面包含 **已归档**、**未归档**、**来源与分支**、**关于**；有旧记录或目录读取异常时显示 **回收站**。

如果设置入口未出现，请核对插件是否安装并启用在实际运行 DSH 的 profile 中，重新加载宿主，并检查[兼容性要求](#兼容性与限制)。

旧版用户更新前，请先阅读下方「升级、旧数据与降级」，尤其是旧快照清理说明。

## 第一次使用：找回并备份一条聊天

1. 打开 **已归档**，输入记得的关键词。如果列表为空，先用 DSH 的会话菜单归档一条已结束的聊天。
2. 点击聊天标题预览对话，确认内容后关闭预览。
3. 点击 **选择**，勾选需要保留的聊天，再选 **导出选中**（窄面板中位于 **更多**），核对选中数量并确认。
4. 在浏览器下载中确认 ZIP 已保存；ZIP 不包含附件文件，需要另行保留。

搜索边界见[归档与查找](#归档与查找)，备份限制与恢复方式见[导出和导入](#导出和导入)。

## 归档与查找

单条聊天仍使用 DSH 原有会话菜单归档。归档后的提示与撤销操作由 Host 自己提供，插件不再额外弹出提示或替换官方归档方法。归档后的聊天在插件中按工作区分组。

已归档和未归档的「所有工作区」菜单使用文件夹图标列出工作区，并提供「未分组」与「定时任务」入口。未分组按官方工作区成员关系判断，不按标题或旧目录推测。定时任务通过官方 `schedule.catalog()` 的会话关联筛选，覆盖仍保留记录的活动及已结束任务；任务被删除后不再匹配，不能把它当作永久的历史会话类型。宿主未启用该服务或读取失败时，入口置灰并提供原因，不影响普通会话列表。

已归档、未归档采用两排工具栏：搜索框独占第一排，筛选控件位于第二排。来源与分支的搜索框独占第一排，相关工作区筛选、会话数量和全部展开／折叠合并在第二排，窄屏按需换行。

已归档和未归档默认按「最近更新」排序，与官方首页一致：以创建时间和最后一次用户发消息时间中的较晚者为准。「最早更新」反向排列；也可按标题排序。助手输出、标签和备注修改不影响该排序。宿主缺少对应时间数据时回退到创建时间；聊天行显示的日期仍为创建时间。

在 **未归档** 中，顶部搜索框独占一排，下一排按时间／标题排序、筛选工作区；右上角的 **刷新** 文字按钮重新加载列表，与 **全部归档** 并列。列表与已归档使用相同的工作区分组及会话行排版。

- 单条聊天点击标题只读预览内容，或点击带图标的「归档」。
- 工作区三个点菜单中的「全部归档」覆盖该工作区。
- 顶部「全部归档」覆盖列表中的所有工作区。

搜索和工作区筛选只改变显示，不缩小工作区或全局归档范围。操作会先检查实际可归档范围；普通单条会话直接归档，不弹出确认。全局和工作区批量归档仍需确认：全局说明所有工作区，工作区保留名称，不显示数量。未归档展示已登记工作区及「未分组」中的已有聊天，排除已确认的空白新建聊天；暂时无法读取内容的聊天仍显示，但暂不可归档。正在运行的聊天可以点击归档：确认窗口提示「停止并归档」，确认后调用官方停止并归档能力。批量归档包含运行中的聊天时也会明确提示停止工作；空白或内容无法确认的聊天不能归档。准备后新增的聊天不纳入此次操作；确认期间才开始运行、未经停止确认的聊天以及改变工作区的聊天会跳过。未归档提供只读预览和归档，不提供勾选、导出、删除或「可清理」入口。归档不更改工作区目录，保留已有标签和备注。取消归档使用官方接口；插件订阅官方工作区状态变化，首页或其他页面的归档操作会同步更新已归档和未归档列表。官方重命名也会同步更新列表标题；未归档列表后台刷新时保留已有条目，首次加载显示「正在加载会话…」。旧 Host 缺少官方停止或取消归档能力时会明确报错，不改写官方状态来模拟。

确认归档后，全部成功会关闭弹窗，使用 Host 原生提示组件显示「归档成功，已归档 N 个会话」和「查看已归档」入口，数量以实际归档结果为准。没有原生提示组件的旧版 Host 会保留结果窗口。有跳过或失败时保留详细结果，不显示全部成功提示。

在「已归档」中可以搜索标题、工作区、标签、备注、消息和工具结果，按类型、工作区、标签筛选，并按时间或标题排序。正文命中会显示摘要；工作区长标题自动换行、完整显示。点击工作区文件夹或标题可展开／收起聊天，文件夹开合样式表示当前状态，分组折叠状态保存在浏览器中。

正文搜索在去除首尾空白后的关键词至少有两个 Unicode 字符时开始。工作区、类型和标签筛选先确定候选范围，客户端每批搜索 20 个候选，API 每次最多接受 100 个明确候选 ID。结果逐步区分已处理候选／总数、正文命中聊天数、当前显示聊天数和失败聊天数。当前显示包含元数据或正文命中的聊天，同一聊天只计一次；这些数量统计聊天而非摘要条数。搜索完成表示已在投影范围内扫描所选候选，不存在 100 个正文命中的总上限；每个命中聊天最多展示三条摘要。更短的关键词仍按列表数据匹配标题、工作区、标签和备注。未归档不搜索聊天正文、工具结果、标签或备注。

「停止搜索」保留已经找到的结果；「重试未完成项」重试未读取及尚未处理的候选，不重复成功命中。读取失败会显示受影响 ID 和原因；网络失败会停止后续批次并保留之前的结果。已移除或变为不可见的候选会标为跳过，不会自动扩大检索范围。更改关键词、筛选条件、会话列表或页面会取消旧检索并丢弃迟到响应。

搜索和预览使用有资源上限的投影，并非无限制原始日志索引：最多 10,000 条投影消息，每条最多 1,000 个片段，每片段最多 256 Ki Unicode 码点，每条消息最多 1 Mi 码点。因此超长日志或内容块可能存在投影范围外的文本，未命中不等于原日志没有匹配内容。

分叉会话读取自身事件流中最后一个有效标题，包括分叉后的重命名。官方分叉创建独立 ID 的新会话，继承分叉点之前的历史，之后独立发展，不会跟随父会话继续同步。新版 Host 上支持预览，以及保留继承历史的 ZIP v2 导出和导入。父会话不存在时也可从 v2 备份恢复；附件文件本体不包含在 ZIP 中，旧版备份与回收站快照回退的限制见「兼容性与限制」。

## 预览、标签与备注

点击搜索摘要会按投影消息序号打开命中附近的一页，高亮并聚焦命中位置，展开折叠轮次内命中的工具或推理文本。「加载更早消息」和「加载更多」保留前后文入口。命中消息已不在投影中时，会明确提示并从开头显示。已归档和未归档都通过点击聊天标题从开头打开预览；悬浮标题或使用键盘聚焦时立即显示「查看对话」提示。回收站和残留会话明细保留预览图标。

无需取消归档即可只读预览对话。支持 Markdown、思考、代码、JSON、工具调用和结果，以及可以读取的已存储图片。没有附件读取能力时，只降级图片；关闭预览会取消未完成请求。

完整加载且有结束记录的轮次，将中间过程归入默认收起的过程折叠项。摘要显示「已思考」或日志中记录的工具、消息、子代理数量；展开后可查看分层的思考、上下文来源、工具摘要及参数和结果，这些详情也默认收起。最终回复独立显示在过程之外。未完整加载或缺少可靠轮次边界的内容保持展开，按事件顺序展示，不强行合并成完整轮次。

系统提示词默认收起，展开后在限高区域内滚动。会话恢复或开启新请求系列时，按记录展示当轮生效的系统提示词；信息不全时不推测。只有真实用户消息显示在右侧；AI 处理过程、思考、工具和注入上下文都在左侧。预览不提供输入框，有宿主 Markdown 渲染器时优先使用；不承诺完整复刻原生会话的所有功能或展示日志中缺失的信息，也不编造用量和耗时。

更新后需要重新加载 DSH 后端才能启用新版预览投影，仅刷新浏览器不会替换正在运行的后端。

点击预览窗口右上角的「编辑标签与备注」图标进行编辑。每条聊天最多 8 个标签，每个标签最多 24 个 Unicode 字符，备注最多 2,000 个 Unicode 字符。标签匹配不区分大小写。列表中备注为单行，截断时可悬停或聚焦查看完整内容。

标签和备注只保存在本机。取消归档不会清除它们；完成永久删除后会清理。

## 操作入口与范围

| 页面与入口 | 可用操作 | 范围 |
| --- | --- | --- |
| 已归档：单条聊天 | 行内为垃圾桶图标（永久删除）、取消归档；点击标题预览，预览右上角直接提供编辑标签备注图标，不提供删除 | 当前聊天 |
| 已归档：工作区「更多」 | 该工作区：全部取消归档、全部导出；分隔线；全部删除 | 该工作区的全部已归档聊天 |
| 未归档：聊天行 | 点击标题预览、归档 | 单条聊天；直接归档，正在执行时确认停止 |
| 未归档：工作区三个点菜单 | 该工作区：全部归档 | 该工作区的所有可归档聊天 |
| 未归档：顶部 | 全部归档 | 所有工作区的可归档聊天 |
| 已归档：顶部 | 选择、三点更多 | 进入选择模式或打开全局操作菜单 |
| 已归档：选择模式 | 全选、取消归档、导出选中、垃圾桶图标（永久删除）、取消 | 操作仅针对勾选聊天；全选仅针对当前结果 |
| 已归档：顶部「更多」 | 导入备份、全部导出、全部取消归档；分隔线；全部删除 | 导出、取消归档及删除覆盖所有工作区的已归档聊天；导入使用所选 ZIP |
| 回收站：单条聊天 | 预览图标、恢复和删除文字按钮 | 当前回收条目；删除需确认且不可恢复 |
| 回收站：工作区「更多」 | 全部恢复、全部删除 | 该工作区的回收条目 |
| 回收站：顶部 | 全部恢复 | 确认后恢复所有工作区的可恢复条目 |
| 回收站：顶部 | 清空回收站 | 确认后永久删除所有工作区的回收条目 |

**选择模式支持单条和多条操作。** 点击「选择」显示复选框和操作栏，行内隐藏操作按钮，点击标题仍可预览；取消归档、导出选中、垃圾桶图标（永久删除）和取消依次直接展示；空间不足时，导出选中收进三点「更多」。未选中会话时，操作按钮禁用，取消仍可用。「全选」勾选当前搜索／筛选结果，部分勾选时显示半选；隐藏的已选项保留并显示数量。取消当前结果的全选不会取消隐藏选择。「取消」或离开已归档会退出模式并清空选择。执行前确认选中数量，失败项保留勾选。普通列表右侧仅保留垃圾桶图标（永久删除）和「取消归档」；点击标题后，预览窗口右上角直接提供「编辑标签与备注」图标，不提供删除或更多菜单；未归档提供只读预览和归档操作。工作区和顶部批量操作不会因搜索、筛选隐藏了部分聊天而缩小范围。

归档工作区菜单中的每项操作都需确认，弹窗保留完整工作区名称。取消归档确认仅说明范围和返回聊天列表的去向，不显示数量；全局操作说明所有工作区，回收站不受影响。取消归档成功后直接更新列表，不额外弹出成功提示；失败仍显示错误。导出、删除等操作仍确认完整范围和数量，筛选不缩小操作范围。各标签的操作按钮位于页面说明文字右侧，与说明使用相同字号；空间不足时换行。切换 Tab 时操作区保留固定空间，避免页面上下跳动。

归档页菜单中的「全部删除」需确认，弹窗会说明不可恢复及影响范围。它不会删除已经在回收站中的聊天。工作区删除只处理归档聊天，不删除工作区或项目文件。

「清空回收站」会捕获确认时展示的精确回收记录实例，包括回收／快照身份。执行时只清理这些已捕获目标：确认后新增的记录不纳入，已变更的目标会失败，而不是重算或扩大范围。无法确定时保留记录，以便之后安全重试；这不是对无关 Host 文件系统内容的删除保证。

## 从回收站恢复

新增移入回收站已停用，本节仅处理旧记录。可导出包含会话和图片的保护快照 ZIP，此格式不能通过普通会话导入器导入。

在回收站中点击单条「恢复」，或使用工作区／顶部「全部恢复」。恢复成功后聊天回到 **已归档**，不会直接回到主页面；要继续聊天，再点击「取消归档」。

如果通过首页的官方操作直接「取消归档」，插件会在确认原会话仍存在且身份一致后解除回收站标记，会话回到「未归档」，标签和备注保留。再次使用官方「归档」会回到「已归档」，不会自动重入回收站。缺失原会话的恢复快照和已开始永久删除的任务不会因此被丢弃或撤销。

工作区「全部恢复」先确认完整工作区名称、可恢复聊天数及去向；顶部「全部恢复」确认整个回收站的工作区数和可恢复聊天数。两种弹窗均说明正在永久删除的跳过数量，取消不会执行恢复。成功提示显示实际恢复数量和「查看已归档」入口；工作区操作还显示工作区名称，部分失败会同时报告未恢复数量和原因。

恢复优先使用仍存在且身份匹配的原会话，不重写原会话内容。只有原件丢失时才尝试用已验证保护快照重建普通会话原 ID，且仅允许 Host 明确的独占写入器。普通 create/append 和无法保留继承边界的 seeded 快照会在写入前拒绝并保留回收记录；不会覆盖已存在的冲突会话。工作区已不存在时，会带警告恢复为未分组归档。

「降级」表示保护数据不可用或不完整，不一定表示聊天无法恢复：原会话仍存在时仍可能恢复。工作区全部恢复会尝试非待删除条目，并报告失败原因；已进入永久删除流程的条目不能恢复。

当前回收站预览仍依赖原会话读取。原件丢失时，即使有可用于恢复的保护快照，也可能无法预览；不要把预览失败直接理解为快照无法恢复。

## 永久删除与失败重试

垃圾桶图标悬浮或获得键盘焦点时提示「删除已归档的聊天」。行内图标执行永久删除，不经过回收站。单条、工作区和全局删除都需确认。选择工具栏直接提供垃圾桶图标（永久删除），已归档聊天预览窗口仅提供编辑入口，不提供删除或更多菜单；工作区和全局菜单使用「全部删除」。删除弹窗分别使用「删除已归档的聊天？」和「删除所有已归档本地聊天？」等标题，点名聊天、工作区或全局范围，并明确永久删除、无法恢复；点击操作只打开确认。回收站也提供单条、工作区永久删除及「清空回收站」。永久删除会清理目标聊天、插件标签备注和关联快照。

开始永久删除后，插件先保存不可恢复的删除任务，再清理关联快照、删除原会话并完成索引清理。中途失败会保留任务和错误提示，由用户在回收站明确重试。待删除项不会继续作为可操作的普通归档显示，也不能恢复或取消归档；即使原会话文件暂时还在，也不代表可以撤销删除。

缺少必要 Host 能力时，操作会在提交删除任务前拒绝执行。删除快照附件副本不保证立即释放 Harness 全局附件库中的相同字节；其他会话引用和 Host 缓存／垃圾回收仍可能保留数据。

永久删除聊天时会连带清理其子代理后代，独立分叉会保留。未归档显示工作区及未分组中的普通聊天。

## 手动检查残留会话

打开 **关于 → 维护工具 → 检查残留会话**。进入归档管理或关于页面不会自动扫描；只有点击按钮才开始检查。运行中显示进度状态，检查失败提供重试，只有成功且结果为空时才显示「未发现残留会话」。关闭弹窗或离开页面会取消进行中的检查。

候选仅包含有明确父来源、父会话已不存在且不属于工作区或已归档列表的子代理会话。未分组的普通聊天、空白聊天、独立分叉，以及父来源缺失或异常的会话不作为此工具的清理对象。它不是全盘垃圾扫描，也不清理全局附件和缓存。

1. 查看候选标题、ID、父来源和目录，点击预览核对内容。
2. 勾选需要保留的内容，选择「导出备份」，到浏览器下载中确认文件已保存。
3. 勾选确实不需要的记录，点击删除并确认不可恢复的后果。执行时重新核对候选身份，只删除所选记录，不自动扩大到其他会话。
4. 查看结果；失败或范围变化会显示错误，随后重新读取列表。可手动「重新检查」。

检查和预览不会删除数据，取消删除确认也不会执行清理。此入口独立于已停用的「空间与策略」。

## 导出和导入

选择模式「导出选中」（窄面板中位于「更多」）备份勾选的聊天，可用于单条备份。顶部「更多 → 全部导出」导出全部已归档聊天；工作区菜单「全部导出」仅导出该工作区的归档聊天。两者都先确认完整范围和聊天数量，不包含回收站内容。旧回收记录可直接「导出快照」保存包含图片的保护包；需要常规会话导入 ZIP 时，先恢复到已归档再导出。「导入备份」也位于顶部「更多」菜单。

每个 ZIP 包含：

```text
manifest.json
sessions/001-<安全标题>-<id>/session.json
sessions/001-<安全标题>-<id>/transcript.md
```

JSON 是机器可读记录，Markdown 是可读副本。新版 Host 导出 ZIP v2，保留分叉会话的精确继承边界；旧读取接口仍导出 v1。两者都保留附件引用，但**不包含附件二进制，也不会自动打包后代会话**；不等于完整附件备份。需要完整会话树时，可查看 Harness 官方 Session log 导出能力。

返回下载流之前，导出会仅读取每个选中来源一次，暂存渲染后的 manifest／会话／Markdown 条目，并执行与导入相同的完整格式和语义验证。因此，本插件成功导出的备份会符合本插件导入器的格式与大小预算。任一来源无效或超限时，整个导出会在成功下载响应前被拒绝，不会产生不完整备份。

共用限制为：最多 2,000 条会话、4,001 个条目；`manifest.json` 和每个会话 JSON 各 4 MiB；任一 ZIP 条目和每个 Markdown 文本各 8 MiB；解压后总量 256 MiB。导入 ZIP 的压缩输入上限为 512 MiB。每个 JSON 还限制深度 64、节点 100,000 个，其所有字符串合计最多 4 Mi Unicode 码点。JavaScript 字符串实际占用的内存可超过编码字节总量。

导入接受本插件 v1 和 v2 ZIP，先预览再确认写入：

- 已存在的会话 ID、回收记录和未完成删除任务均标为冲突、禁用并跳过，不覆盖原会话。
- 缺少对应工作区时，带警告导入为未分组归档聊天。
- 标签和备注遵守相同长度限制。
- 确认过期后需要重新预览；缺少恢复写入能力时拒绝执行。

导入后会话回到「已归档」，保留原 ID、标题、事件及标签备注；先预览确认，再「取消归档」回到主聊天列表。新版 Host 导入会明确持久化并释放写入占用。若写入失败后残留文件的归属无法确认，会明确提示回滚未完成并保留文件；请保留 ZIP，排查后再重试，不要为消除冲突而直接删除已有聊天。

导入要求 ZIP 完整且内部一致，会拒绝截断、CRC 或本地／中央目录不一致、无效 UTF-8、不安全路径或 JSON 键、重复／未引用条目、加密、ZIP64、多磁盘归档，以及 Store／Deflate 之外的压缩方式。普通 v1 备份仍受支持，但没有精确继承边界的 seeded v1 来源会被拒绝，不会被展平。

浏览器会在发起下载前缓冲并验证完整 ZIP。响应字节上限为 320 MiB，完整获取／读取响应体的超时为五分钟；这不是峰值堆内存保证，当前非流式兼容路径也没有更强的通用 WebView 内存承诺。“已开始下载”不表示浏览器已将文件保存到磁盘。超时或超限时不会下载不完整文件，可重试。

导出按 256 KiB 分片压缩已暂存的条目，并在分片之间让出事件循环，因此生成大型备份时不会长时间占用 Host 主线程。下载被取消时归档立即停止且响应失败，已取消的导出不会被报告为完成。

ZIP 导入和回收站恢复是两套不同流程，不要把 ZIP 当作回收站保护快照使用。

## 来源与分支

会话范围说明收起到会话数量旁的提示图标；将鼠标放上去、用键盘聚焦或触屏点击即可查看。

以官方已归档会话为中心，展示父级来源和下级分支，包括相关的未归档会话、子智能体及未分组会话。无关的未归档会话和空工作区不展示。保留当前归档和回收站状态标识；没有官方会话记录的回收站快照不会单独加入关系树。

会话按实际所属工作区分组，工作区标题显示数量，折叠状态保存在浏览器。卡片沿用内置插件页面的圆角、边框、标题字号与间距，右侧只有一个展开入口，同时显示详情和下级分支；不再另外放置「详情」折叠箭头。未分组聊天有独立分组。

未归档会话与已归档会话同样计入所属工作区。跨工作区重复的父会话、筛选后保留的父级及无法读取的来源作为只读参考节点，不重复计入当前结果数量。每张卡片分别展示当前状态（未归档、已归档、回收站、来源不可用）和关系类型（原始会话、分支会话、子智能体）。信息不足时显示「来源待确认」，不推断为原始会话或已删除。

深层分叉最多显示两列祖先引导线加当前连接线，更深层级显示层级数。跨工作区会话仍只在所属工作区计入管理数量，其他工作区需要它解释来源时会标明只读参考。

搜索框独占第一排；相关工作区筛选、会话数量、范围说明入口和全部展开／折叠合并在第二排，窄屏按需换行。不提供状态筛选。搜索会话或来源名称会保留必要父级并临时展开匹配路径。清空搜索后恢复原折叠状态。「全部展开／折叠」作用于当前结果的工作区、卡片详情和分支。完整标题、时间、来源 ID 和复制会话 ID 位于展开区域。

关系读取官方 `parentSession`、`isSeeded` 和子智能体来源字段。v4 的精确继承事件数不在会话头中，本页不臆测该数值；旧格式的继承长度仅用于兼容。页面只读，不修改会话关系，也不复制归档和回收站的管理操作。回收站记录不可读时，仍展示官方会话与归档状态，并提示回收站标记暂不可用。单次关系图上限为 5,000 个节点，超出时明确报错，不静默截断。

## 关于与更新

从 1.4.1 起，仅确认有新版本时，「关于」标签右上角显示红点；尚未检查、检查失败或已是最新版时不显示。打开「关于」不会清除仍可用的新版本提示。

插件内部归档成功使用 Host 原生提示组件，停留 6 秒后按原生动画淡出；主聊天页面的归档提示完全由 Host 控制。其他操作的成功提示（包括回收站恢复后的「查看已归档」）在 4 秒后自动收起，鼠标悬停或键盘焦点停留时暂停计时。切换标签会清除当前提示；错误提示不会自动消失，可以手动关闭。

「关于」依次展示产品说明与项目信息、版本与更新、维护工具。保留作者、许可证，以及项目主页、对应语言的使用指南、更新日志、问题反馈和插件市场链接。维护工具提供手动「检查残留会话」，不恢复空间策略或定时清理。页面标题旁也显示当前运行版本。

「当前版本」动态读取正在运行的后端，不使用网上最新版代替。联网检查失败不会清除已读取的版本、作者或链接；本地信息读取失败则显示「暂不可用」和「重新读取」，不误报为检查更新失败。若刚更新插件但新接口尚未加载，请重新加载 DSH 后端后重试。

打开归档管理时先读取本地信息，再自动查询公开 npm 版本；页面保持打开时每 15 分钟进行缓存感知检查，重新显示或联网时也会补查。成功结果缓存 12 小时，失败结果缓存 15 分钟；手动检查使用 30 秒短限流，并发请求合并。只查询公开版本，不发送聊天或备份内容；失败不阻塞会话管理，也不显示「已是最新版」。关闭页面会清理定时器和事件监听。

更新后版本未变化时，还应核对更新的 profile 是否就是实际运行 DSH 的 profile。

「检查更新」与标题旁的「查看更新」打开更新弹窗，展示运行版本、公开版本、上次检查和当前环境。支持复制包名到另一端的「添加插件」；命令只在能验证当前启动程序和 profile 时提供，官方桌面端使用其自带命令，不依赖 PATH 中的另一套 dsh。这里只识别当前环境，不扫描或自动安装到其他桌面端。

本地 `link:` / `file:` 等来源标记为「本地开发版」，提供复制本地路径，后端拒绝用线上包覆盖。普通 npm 安装仅在宿主插件管理器允许原地更新时显示「安装更新」；官方 HMR 模式要求重新安装时，保留宿主限制并给出手动指引。点击安装仅提交已展示的精确版本，宿主负责兼容性、安装锁和安装脚本检查；插件不绕过这些限制。失败不宣称完成，重复提交被阻止。安装成功后显示待重启，运行版本直到后端重启才改变；不会自动重启 DSH。

## 升级、旧数据与降级

**回收站过渡调整：** 已停止新增回收，删除操作需要明确确认永久删除。旧回收记录不自动迁移或清空；有记录时保留恢复、导出保护快照和确认删除入口，处理完后隐藏。空间与策略入口、自动到期清理、启动快照清扫均已停用，旧策略文件保留但不执行。原件缺失且恢复不受支持时保留记录并报告失败。保护快照导出包含图片，单条上限 64 MiB，不是常规会话导入 ZIP。

## 兼容性与限制

- **设置弹窗自动关闭（宿主已知问题）：** DSH `0.2.1-rc.2` 在首次配置未完成时，归档当前聊天可能触发引导并关闭设置。此问题已反馈至官方 [#10596](https://github.com/deepseek-ai/deepseek-harness/discussions/10596)，不代表归档失败；可重新打开设置核对结果。本插件 1.6.0 不包含宿主修复。

功能取决于 Host 公开能力，不仅取决于版本号：

- 没有公开归档能力时，工作区批量归档不可用。
- 没有会话独占物理位置时，会话目录统计及永久删除不可用；插件不会猜测路径或删除共享目录。
- 回收站原件恢复不要求重写日志；快照回退和 ZIP 导入要求相应公开写入能力。
- 新版 Host 的 ZIP v2 支持继承历史分叉的导出和导入，父会话不存在也可恢复；旧 v1 备份缺少继承边界时，不能安全重建 seeded 会话，会明确拒绝。回收站恢复是独立流程：原件存在时不重写；原件缺失时，其旧快照回退写入器仍拒绝重建分叉并保留保护记录。
- ZIP 恢复支持已验证的现代 create 句柄和专用／独占 writer 合约。没有明确独占创建保证的普通旧 create/append 不受支持，因为目录中不存在记录并不能证明安全所有权。
- 取消归档需要权威、可读的持久化 header 及工作目录。没有工作目录的聊天会安全保留在已归档，仍可预览／导出；这与工作区缺失不同，后者可降级为未分组归档聊天。可选冷标题发布可能在持久恢复成功后给出警告，不会回滚或破坏已恢复数据。
- v2 保护快照需要此版或更新的插件读取；回退旧插件前先恢复需要保留的回收聊天，并备份插件数据。
- 如果 `trash.json` 无法读取，归档列表会标为未经核对，回收站不可用，并拒绝取消归档、编辑标签备注及删除等归档修改，避免猜测状态。

声明的 DSH `>=0.1.0-rc.7` 范围仍表达基于 Host 公开能力的兼容性。发布自动化在 Ubuntu 上测试 Node.js 18，并在 Ubuntu、macOS 和 Windows 上测试 Node.js 24；Node.js 24 矩阵强制运行官方 `@deepseek-ai/dsh-session@0.1.7-rc.2` 与 `0.2.1-rc.2` 两套锁定 Host 后端集成（各 8 项）与打包检查，覆盖 v4 会话格式。

## 本地数据与卸载

插件状态位于：

```text
$DSH_HOME/plugin-data/archived-chats/
```

| 文件 | 用途 |
| --- | --- |
| `metadata.json` | 标签和备注 |
| `trash.json` | 回收记录与待完成的永久删除任务 |
| `retention.json` | 保留的旧清理策略，当前不执行 |
| `snapshots/` | 回收恢复所需保护数据及等待清理的遗留快照 |
| `pending-deletions.json`（旧版遗留） | 旧删除标记迁移输入 |
| `legacy-recycle.json`（旧版遗留） | 新版不再使用的旧快照迁移状态 |

插件不会上传、云同步或定时抓取历史版本。卸载命令：

```sh
dsh plugin --profile web remove dsh-archived-chats
```

卸载保留插件数据，不执行永久删除。本过渡版本不会启动自动清理；安装旧版前应核对其清理行为。不要把手动删除插件目录当作「清空回收站」：这会丢失恢复信息，却未必删除 Host 保存的会话。需要清理时优先使用界面，并先备份仍需保留的数据。
