# 归档管理用户指南

[English](USER_GUIDE.md) · 简体中文 · [返回 README](../README.zh-CN.md)

归档管理为 DSH 已归档聊天提供查看和管理页面，并扩展按工作区批量归档。本文跟随 `main` 分支维护。本文适用于 1.4.1，包含英文名称统一与交互提示优化；已安装用户请参阅升级说明中的版本差异。版本变更见[更新日志](../CHANGELOG.md)。接口和数据格式见[架构说明](ARCHITECTURE.md)。

## 先理解三个位置

| 位置 | 用途 | 如何返回主页面 |
| --- | --- | --- |
| 主页面会话区 | 日常继续聊天 | 已在主页面 |
| 已归档 | 保留聊天，但不在主页面会话区显示 | 点击「取消归档」 |
| 回收站 | 暂时移出归档列表，保留恢复机会 | 先「恢复」到已归档，再「取消归档」 |

归档不等于删除，也不创建历史版本。移入回收站不立即删除原会话文件，但需要保护快照。永久删除不可恢复，不是移入回收站。

## 安装与打开

在 DSH 插件市场搜索 `dsh-archived-chats`，核对作者为 **Ultronen** 后点击「安装」。安装完成后按宿主提示重启 DSH，打开 **设置 → 归档管理**。

也可以在运行 DSH 的电脑上使用命令行安装：

```sh
dsh plugin --profile web add dsh-archived-chats@latest
```

重启 DSH，打开 **设置 → 归档管理**。页面包含 **已归档**、**回收站**、**空间与策略**、**来源与分支**、**关于**。

旧版用户更新前，请先阅读下方「升级、旧数据与降级」，尤其是旧快照清理说明。

## 归档与查找

单条聊天仍使用 DSH 原有会话菜单归档。成功后提示提供「查看」和「撤销」，约 3 秒后关闭。归档后的聊天在插件中按工作区分组。

需要批量归档时：

1. 在设置页点击「批量归档」。
2. 在工作区选择器中选择一个或多个工作区；「全选」再次点击会取消全选。
3. 点击右下角「确定」，核对汇总的聊天数量和归档去向。
4. 确认归档；如果有跳过或失败，查看保留的逐项结果。

选择器仅展示存在可归档聊天的工作区。空白新会话、正在使用或无法确认内容的聊天会被跳过。准备后新增的聊天不纳入本次操作；工作区变空时会跳过。操作不移动聊天所属工作区，也不更改工作区目录。

在「已归档」中可以搜索标题、工作区、标签、备注、消息和工具结果，按类型、工作区、标签筛选，并按时间或标题排序。正文命中会显示摘要；工作区长标题自动换行、完整显示。点击工作区文件夹或标题可展开／收起聊天，文件夹开合样式表示当前状态，分组折叠状态保存在浏览器中。

分叉会话读取自身事件流中最后一个有效标题，包括分叉后的重命名。官方分叉创建独立 ID 的新会话，继承分叉点之前的历史，之后独立发展，不会跟随父会话继续同步。新版 Host 上支持预览、移入回收站，以及保留继承历史的 ZIP v2 导出和导入。父会话不存在时也可从 v2 备份恢复；附件文件本体不包含在 ZIP 中，旧版备份与回收站快照回退的限制见「兼容性与限制」。

## 预览、标签与备注

无需取消归档即可只读预览对话。支持 Markdown、思考、代码、JSON、工具调用和结果，以及可以读取的已存储图片。没有附件读取能力时，只降级图片；关闭预览会取消未完成请求。

完整加载且有结束记录的轮次，将中间过程归入默认收起的过程折叠项。摘要显示「已思考」或日志中记录的工具、消息、子代理数量；展开后可查看分层的思考、上下文来源、工具摘要及参数和结果，这些详情也默认收起。最终回复独立显示在过程之外。未完整加载或缺少可靠轮次边界的内容保持展开，按事件顺序展示，不强行合并成完整轮次。

系统提示词默认收起，展开后在限高区域内滚动。会话恢复或开启新请求系列时，按记录展示当轮生效的系统提示词；信息不全时不推测。只有真实用户消息显示在右侧；AI 处理过程、思考、工具和注入上下文都在左侧。预览不提供输入框，有宿主 Markdown 渲染器时优先使用；不承诺完整复刻原生会话的所有功能或展示日志中缺失的信息，也不编造用量和耗时。

更新后需要重新加载 DSH 后端才能启用新版预览投影，仅刷新浏览器不会替换正在运行的后端。

每条聊天最多 8 个标签，每个标签最多 24 个 Unicode 字符，备注最多 2,000 个 Unicode 字符。标签匹配不区分大小写。列表中备注为单行，截断时可悬停或聚焦查看完整内容。

标签和备注只保存在本机。取消归档不会清除它们；完成永久删除后会清理。

## 操作入口与范围

| 页面与入口 | 可用操作 | 范围 |
| --- | --- | --- |
| 已归档：单条聊天 | 预览、编辑标签备注、取消归档、删除 | 当前聊天 |
| 已归档：工作区「更多」 | 全部取消归档、全部移入回收站、全部导出；分隔线；全部删除 | 该工作区的全部已归档聊天 |
| 已归档：顶部 | 批量归档、更多 | 打开工作区选择器或全局操作菜单 |
| 已归档：顶部「更多」 | 导入备份、全部导出、全部取消归档；分隔线；全部删除 | 导出、取消归档及删除覆盖所有工作区的已归档聊天；导入使用所选 ZIP |
| 回收站：单条聊天 | 预览图标、恢复和删除文字按钮 | 当前回收条目；删除需确认且不可恢复 |
| 回收站：工作区「更多」 | 全部恢复、全部删除 | 该工作区的回收条目 |
| 回收站：顶部 | 全部恢复 | 确认后恢复所有工作区的可恢复条目 |
| 回收站：顶部 | 清空回收站 | 确认后永久删除所有工作区的回收条目 |

**移入回收站只提供工作区入口，不提供单条或顶部全部移入入口。** 不提供单条导出或列表多选模式。工作区和顶部批量操作不会因搜索、筛选隐藏了部分聊天而缩小范围。

归档工作区菜单中的每项操作都需确认，弹窗显示完整工作区名称及该工作区全部归档聊天数。全局「全部导出」「全部取消归档」「全部删除」确认统计所有工作区的归档聊天，不包含回收站；筛选列表后仍应核对完整数量。切换 Tab 时顶部操作区保持一致尺寸。

归档页的「全部删除」是永久删除，不是移入回收站；弹窗会说明不可恢复及影响范围。它不会删除已经在回收站中的聊天。工作区删除只处理归档聊天，不删除工作区或项目文件。

「清空回收站」会捕获确认时展示的精确回收记录实例，包括回收／快照身份。执行时只清理这些已捕获目标：确认后新增的记录不纳入，已变更的目标会失败，而不是重算或扩大范围。无法确定时保留记录，以便之后安全重试；这不是对无关 Host 文件系统内容的删除保证。

## 从回收站恢复

通过工作区菜单「全部移入回收站」操作时，每条聊天先创建或复用健康的保护快照，再写入回收记录。失败的聊天不会被当作成功回收；成功提示提供立即「撤销」。

在回收站中点击单条「恢复」，或使用工作区／顶部「全部恢复」。恢复成功后聊天回到 **已归档**，不会直接回到主页面；要继续聊天，再点击「取消归档」。

工作区「全部恢复」先确认完整工作区名称、可恢复聊天数及去向；顶部「全部恢复」确认整个回收站的工作区数和可恢复聊天数。两种弹窗均说明正在永久删除的跳过数量，取消不会执行恢复。成功提示显示实际恢复数量和「查看已归档」入口；工作区操作还显示工作区名称，部分失败会同时报告未恢复数量和原因。

恢复优先使用仍存在且身份匹配的原会话，不重写原会话内容。只有原件丢失时才尝试用已验证保护快照重建普通会话原 ID，且仅允许 Host 明确的独占写入器。普通 create/append 和无法保留继承边界的 seeded 快照会在写入前拒绝并保留回收记录；不会覆盖已存在的冲突会话。工作区已不存在时，会带警告恢复为未分组归档。

「降级」表示保护数据不可用或不完整，不一定表示聊天无法恢复：原会话仍存在时仍可能恢复。工作区全部恢复会尝试非待删除条目，并报告失败原因；已进入永久删除流程的条目不能恢复。

当前回收站预览仍依赖原会话读取。原件丢失时，即使有可用于恢复的保护快照，也可能无法预览；不要把预览失败直接理解为快照无法恢复。

## 永久删除与失败重试

单条、工作区和全局删除都需确认。归档行使用文字「删除」，位于「取消归档」右侧；工作区和全局菜单使用「全部删除」。简短确认弹窗会点名聊天或工作区，或说明全局完整范围，并明确删除不可恢复；点击操作只打开确认。回收站也提供单条、工作区永久删除及「清空回收站」。永久删除会清理目标聊天、插件标签备注和关联快照。

开始永久删除后，插件先保存不可恢复的删除任务，再清理关联快照、删除原会话并完成索引清理。中途失败会保留任务和错误提示，在运行期间或下次启动时继续重试。待删除项不会继续作为可操作的普通归档显示，也不能恢复或取消归档；即使原会话文件暂时还在，也不代表可以撤销删除。

缺少必要 Host 能力时，操作会在提交删除任务前拒绝执行。删除快照附件副本不保证立即释放 Harness 全局附件库中的相同字节；其他会话引用和 Host 缓存／垃圾回收仍可能保留数据。

## 导出和导入

顶部「更多 → 全部导出」导出全部已归档聊天；工作区菜单「全部导出」仅导出该工作区的归档聊天。两者都先确认完整范围和聊天数量，不包含回收站内容。需要备份回收聊天时，先恢复到已归档。「导入备份」也位于顶部「更多」菜单。

每个 ZIP 包含：

```text
manifest.json
sessions/001-<安全标题>-<id>/session.json
sessions/001-<安全标题>-<id>/transcript.md
```

JSON 是机器可读记录，Markdown 是可读副本。新版 Host 导出 ZIP v2，保留分叉会话的精确继承边界；旧读取接口仍导出 v1。两者都保留附件引用，但**不包含附件二进制，也不会自动打包后代会话**；不等于完整附件备份。需要完整会话树时，可查看 Harness 官方 Session log 导出能力。

返回下载流之前，导出会仅读取每个选中来源一次，暂存渲染后的 manifest／会话／Markdown 条目，并执行与导入相同的完整格式和语义验证。因此，本插件成功导出的备份会符合本插件导入器的格式与大小预算。任一来源无效或超限时，整个导出会在成功下载响应前被拒绝，不会产生不完整备份。

共用限制为：最多 2,000 条会话、4,001 个条目；`manifest.json` 和每个会话 JSON 各 4 MiB；任一 ZIP 条目和每个 Markdown 文本各 8 MiB；解压后总量 256 MiB。导入 ZIP 的压缩输入上限为 512 MiB。每个 JSON 还限制深度 64、节点 100,000 个，其所有字符串合计最多 4 Mi Unicode 码点。JavaScript 字符串实际占用的内存可超过编码字节总量。

导入接受本插件 v1 和 v2 ZIP，先预览再确认写入：

- 已存在的会话 ID、回收记录和未完成删除任务均标为冲突、禁用并跳过，不覆盖原会话。
- 缺少对应工作区时，带警告导入为未分组归档聊天。
- 标签和备注遵守相同长度限制。
- 确认过期后需要重新预览；缺少恢复写入能力时拒绝执行。

导入后会话回到「已归档」，保留原 ID、标题、事件及标签备注；先预览确认，再「取消归档」回到主聊天列表。新版 Host 导入会明确持久化并释放写入占用。若写入失败后残留文件的归属无法确认，会明确提示回滚未完成并保留文件；请保留 ZIP，排查后再重试，不要为消除冲突而直接删除已有聊天。

导入要求 ZIP 完整且内部一致，会拒绝截断、CRC 或本地／中央目录不一致、无效 UTF-8、不安全路径或 JSON 键、重复／未引用条目、加密、ZIP64、多磁盘归档，以及 Store／Deflate 之外的压缩方式。普通 v1 备份仍受支持，但没有精确继承边界的 seeded v1 来源会被拒绝，不会被展平。

浏览器会在发起下载前缓冲并验证完整 ZIP。响应字节上限为 320 MiB，完整获取／读取响应体的超时为五分钟；这不是峰值堆内存保证，当前非流式兼容路径也没有更强的通用 WebView 内存承诺。“已开始下载”不表示浏览器已将文件保存到磁盘。超时或超限时不会下载不完整文件，可重试。

ZIP 导入和回收站恢复是两套不同流程，不要把 ZIP 当作回收站保护快照使用。

## 空间与自动清理

空间统计区分归档／回收会话目录、当前回收记录引用的保护快照、不可用或降级的测量，以及重复快照附件字节。明细可在可搜索弹窗中查看；统计不是整个 Harness 目录的占用，也不等于全局可释放空间。

**回收站自动清理默认关闭。** 可选择 7 天、30 天、90 天或自定义 1–3650 个整数天数，从每条聊天移入回收站的时间起计算。首次开启或缩短期限时，弹窗会列出已到期内容并说明未来删除行为；保存确认后不再逐次询问。

DSH 运行时约每分钟检查，关闭期间暂停，启动恢复完成后补检。只删除到期回收条目，不清空未到期聊天。关闭或延长期限可以直接保存；已经进入永久删除流程的任务仍会继续完成。旧版保存的保留天数不会自动启用清理。

这与下面的旧快照清理是两件事：**关闭回收站自动清理，并不会阻止启动时清理未被引用的旧快照。**

## 来源与分支

1.4.1 将管理范围说明收起到「已管理会话」旁的提示图标；将鼠标放上去、用键盘聚焦或触屏点击即可查看。存储页「回收站自动清理」旁也使用相同的说明入口，开启清理时的永久删除确认仍会完整显示。

只读展示归档和回收聊天的来源、分叉、子代理树，以及解释这些关系所需的活动会话上下文，不列出无关活动聊天。

会话按实际所属工作区分组，工作区标题显示数量，折叠状态保存在浏览器。每条使用紧凑关系行，标题左侧箭头展开分支；默认先展示起始会话，不自动铺开全部后代。「详情」按需显示完整标题、时间、来源和会话 ID，并保留复制 ID。未分组聊天有独立分组。

深层分叉不再无限增加横向缩进：最多显示两列祖先引导线加当前连接线，更深层级显示层级数，父会话名称与来源 ID 仍可核对。跨工作区分叉归入自身工作区，标明来源工作区，不复制为多个可管理条目。

搜索临时展开命中的工作区和分支，清空后恢复原折叠状态。筛选保留必要来源说明；「全部展开／折叠」作用于当前筛选结果的工作区和分支。缺失父节点、循环或未知字段会显示诊断或降级，不修改会话关系。

## 关于与更新

从 1.4.1 起，仅确认有新版本时，「关于」标签右上角显示红点；尚未检查、检查失败或已是最新版时不显示。打开「关于」不会清除仍可用的新版本提示。

归档管理页面内的操作成功提示（包括恢复后的「查看已归档」）在 4 秒后自动收起，鼠标悬停或键盘焦点停留时暂停计时。切换标签会清除当前提示；错误提示不会自动消失，可以手动关闭。主聊天页面的原生归档成功提示仍约 3 秒后关闭。这些交互改进自 1.4.1 起提供。

「关于」展示正在运行的插件版本、作者、许可证，并直达项目主页、对应语言的使用指南、更新日志、问题反馈和插件市场。页面标题旁也显示当前运行版本。

「当前版本」动态读取正在运行的后端，不使用网上最新版代替。联网检查失败不会清除已读取的版本、作者或链接；本地信息读取失败则显示「暂不可用」和「重新读取」，不误报为检查更新失败。若刚更新插件但新接口尚未加载，请重新加载 DSH 后端后重试。

打开归档管理时先读取本地信息，再在后台查询公开 npm 包版本。自动检查结果（含失败）在后端运行期间缓存 12 小时；「检查更新」可绕过这段缓存，但有 30 秒短间隔限制，并发检查共用一次请求。不发送聊天或备份内容；网络失败会明确提示，既不阻断归档操作，也不误报已是最新版。

检测到新版时，标题旁显示「去更新」，点击打开插件市场。插件不会下载或安装更新、执行命令、自动重启 DSH。完成更新后按宿主提示自行选择重启时机；仅刷新页面不一定能启用新版后端，显示的版本以实际已加载版本为准。

## 升级、旧数据与降级

**名称与版本：** 1.4.1 的英文名称为 Archive Management，1.4.0 英文菜单显示 Session Archive；两者都对应中文「归档管理」，不是不同插件。中文入口、包名、安装命令和数据位置不变。更新至 1.4.1 或更高版本并重启 DSH 后，英文入口名称生效。

独立「历史版本」和「预览清理」界面已退役。归档不再创建历史版本；回收站保护快照只用于恢复，不是用户可以浏览的历史版本库。

**从旧版本升级并启动新版后，启动恢复流程会自动删除没有被当前回收记录引用的旧快照，包括相应的插件附件副本；这些快照不会转成回收站条目，也无法通过插件恢复。** 当前回收记录引用的保护快照会保留。此清理不删除来源聊天本身；已确认的待删除任务重试及已启用的到期清理是另外的机制。

如果还需要旧快照内容，请在升级前用支持该功能的旧版恢复并导出，并另行保存需要的附件；也可先离线备份完整插件数据目录。尚未处理的旧版删除标记会尝试迁移为可恢复回收记录，不会仅凭旧标记在启动时直接删除聊天。

降级前应先完成待删除任务并备份插件数据。旧版本可能无法识别新版待删除记录，特别是不带保护快照的直接永久删除任务。

## 兼容性与限制

功能取决于 Host 公开能力，不仅取决于版本号：

- 没有公开归档能力时，工作区批量归档不可用。
- 没有会话独占物理位置时，会话目录统计及永久删除不可用；插件不会猜测路径或删除共享目录。
- 回收站原件恢复不要求重写日志；快照回退和 ZIP 导入要求相应公开写入能力。
- 新版 Host 的 ZIP v2 支持继承历史分叉的导出和导入，父会话不存在也可恢复；旧 v1 备份缺少继承边界时，不能安全重建 seeded 会话，会明确拒绝。回收站恢复是独立流程：原件存在时不重写；原件缺失时，其旧快照回退写入器仍拒绝重建分叉并保留保护记录。
- ZIP 恢复支持已验证的现代 create 句柄和专用／独占 writer 合约。没有明确独占创建保证的普通旧 create/append 不受支持，因为目录中不存在记录并不能证明安全所有权。
- 取消归档需要权威、可读的持久化 header 及工作目录。没有工作目录的聊天会安全保留在已归档，仍可预览／导出；这与工作区缺失不同，后者可降级为未分组归档聊天。可选冷标题发布可能在持久恢复成功后给出警告，不会回滚或破坏已恢复数据。
- v2 保护快照需要此版或更新的插件读取；回退旧插件前先恢复需要保留的回收聊天，并备份插件数据。
- 如果 `trash.json` 无法读取，归档列表会标为未经核对，回收站不可用，并拒绝取消归档、编辑标签备注及删除等归档修改，避免猜测状态。

声明的 DSH `>=0.1.0-rc.7` 范围仍表达基于 Host 公开能力的兼容性。发布自动化已通过 Ubuntu 上的 Node.js 18，以及 Ubuntu、macOS 和 Windows 上的 Node.js 24；Node.js 24 矩阵强制运行官方 Host 后端集成（5/5）与打包检查。已安装的 1.4.0 产物也已在 `@deepseek-ai/dsh-session@0.1.5-rc.2` 上通过官方 native 闭环（5/5）。

## 本地数据与卸载

插件状态位于：

```text
$DSH_HOME/plugin-data/archived-chats/
```

| 文件 | 用途 |
| --- | --- |
| `metadata.json` | 标签和备注 |
| `trash.json` | 回收记录与待完成的永久删除任务 |
| `retention.json` | 自动清理策略 |
| `snapshots/` | 回收恢复所需保护数据及等待清理的遗留快照 |
| `pending-deletions.json`（旧版遗留） | 旧删除标记迁移输入 |
| `legacy-recycle.json`（旧版遗留） | 新版不再使用的旧快照迁移状态 |

插件不会上传、云同步或定时抓取历史版本。卸载命令：

```sh
dsh plugin --profile web remove dsh-archived-chats
```

卸载保留插件数据，不执行永久删除。重新安装后的启动仍会执行当前版本的恢复与清理规则，所以保留目录不等于永久保留旧快照。不要把手动删除插件目录当作「清空回收站」：这会丢失恢复信息，却未必删除 Host 保存的会话。需要清理时优先使用界面，并先备份仍需保留的数据。
