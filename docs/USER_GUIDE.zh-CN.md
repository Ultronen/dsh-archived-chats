# 会话档案用户指南

[English](USER_GUIDE.md) · 简体中文 · [返回 README](../README.zh-CN.md)

本指南说明会话档案的完整用户流程、数据边界与恢复行为。Host 路由、事务和维护者实现请参阅 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 归档并查找聊天

1. 从 DSH 正常会话菜单归档聊天。
2. Host 确认成功后，全局提示提供 **查看** 和 **撤销**，并在 3 秒后关闭。归档不会保存快照。
3. 打开 **设置 → 会话档案**，**归档** 视图会按工作区分组显示全部可见归档聊天。
4. 使用同一个搜索框匹配标题、工作区、标签、备注、用户消息、助手回答和工具结果；正文命中会显示可读摘要。

分组折叠状态会保存在浏览器中。你可以按普通会话或子代理会话、项目和标签筛选，再按最新、最早或标题排序。

## 归档整个工作区

打开 **设置 → 会话档案**，选择 **批量归档工作区**。选择器只展示当前至少有一条可归档会话的工作区。可选择一个或多个工作区，也可使用 **全选**；再次点击“全选”会取消全部选择。未选择时，右下角 **确定** 保持禁用。

点击 **确定** 后，插件会准备所有所选工作区，并打开一次包含符合条件会话总数和 **已归档** 去向的汇总确认。准备期间变为空的工作区会自动跳过；如果全部变为空，会刷新并返回选择器，不再弹出“没有可归档会话”的额外提示。存在正在使用的会话时，还会显示将跳过的数量，但不会列出会话身份；没有会话预览列表或第二次确认。

选择 **全部归档** 继续，或选择 **取消** 并保持所有数据不变。符合条件是指聊天当前尚未归档、没有处于非空闲状态的 Host agent，并且检查到其活动或持久化事件日志包含 `turn/start`。因此，空白的新会话窗口不属于可归档会话。旧版 Host 不提供 agent 状态时，已加载会话会被保守跳过；插件无法确认事件内容时也会跳过，而不会猜测。准备最多包含 2,000 条符合条件的聊天，并签发 5 分钟有效、只能使用一次的 token 和 nonce，绑定精确且有序的集合；执行请求不能追加 ID，准备之后新增的聊天也不会被纳入。

执行时，每条已准备会话都会重新检查工作区归属、归档状态、agent 活动状态和真实 `turn/start`。每个工作区保留独立确认凭据，客户端按选择顺序执行后汇总结果。全部成功后会刷新受影响视图并关闭确认框；存在跳过或失败时，Host 仍会继续处理其余项目，并保留逐项结果。不确定失败后必须重新准备，并再次明确确认才能重试。此操作不会在工作区之间移动聊天，不会修改所选工作区或其目录。没有公开 `archiveSession` 的 Host 会以 `workspace-archive-unsupported` 拒绝准备请求，且不作任何修改。

## 原生只读预览

无需取消归档即可预览。预览沿用 Harness 对话布局，并支持：

- Markdown、思考过程、代码、JSON、工具调用和工具结果。
- 通过受保护本地路由读取可用的已存储图片。
- 响应式轮次导航和清楚的只读状态。
- 安全降级：附件读取不可用时，文本和工具内容仍可阅读。

关闭预览会取消尚未完成的图片和分页请求，预览不会修改来源会话。

## 标签、备注与列表操作

- 每条聊天最多可添加 8 个标签，每个标签最多 24 个 Unicode 字符；备注最多 2,000 个 Unicode 字符。
- 标签匹配不区分大小写；每行最多直接显示 3 个标签，其余折叠为 `+N`。
- 备注在列表中单行显示，超出部分以省略号截断；仅在内容被截断时，鼠标悬停或键盘聚焦可查看完整浮层，长内容可滚动，Esc 关闭。标签与备注合并为一行，创建时间和大小显示在底部；普通聊天为两行，有标签或备注时为三行。正文搜索命中会额外显示匹配摘要。
- 搜索框位于归档内容顶部；下方保留“全部聊天”“所有项目”“全部标签”三个入口，类型和排序方式合并在“全部聊天”菜单中。每个项目的聊天共用一个圆角外框，以细线分隔。界面以桌面网页与客户端窗口为主。
- 标签和备注只保存在本地 `metadata.json`。取消归档会保留它们，物理删除完成后才会移除。
- 单条操作依次提供预览图标、标签备注编辑图标、永久删除图标和“取消归档”；永久删除会打开该聊天的确认框。单条导出和行内更多菜单已取消。归档工作区菜单依次为：**全部导出**、**全部取消归档**、**全部永久删除**、**全部移至回收站**；范围包含该工作区中被筛选隐藏的聊天。
- 标题行右上角保留归档备份操作和“全部删除”。全部删除会永久移除所有工作区中的归档聊天、标签、备注和关联快照，不影响回收站内容。
- 回收站每行使用预览、恢复和永久删除图标。每个工作区的三点菜单提供 **全部恢复** 和 **全部永久删除**；全部恢复会跳过降级或其他无法恢复的快照，工作区永久删除会覆盖该工作区中的每一条回收内容。“清空回收站”位于标题行右上角，确认后永久删除所有工作区的回收会话和保护快照。
- 不再提供多选模式。单条操作使用行内按钮，工作区操作使用项目“更多”菜单，全部归档或全部回收内容使用标题行操作。

## 已有快照

主导航为 **已归档**、**回收站**、**空间与策略** 和 **来源与分支**。独立历史版本功能已取消，普通归档和工作区批量归档都不再创建版本。

升级不会删除已有快照，它们会直接显示在 **回收站**。可读取的保护快照支持只读预览、恢复为新的归档副本或确认永久删除，恢复不会覆盖来源聊天。无法读取的快照会标记为降级，只能永久删除。

需要长期保存时，请主动导出备份。回收站恢复用于找回删除的聊天。

## 导出、导入与恢复

可以从标题行导出全部归档，或从工作区菜单导出该工作区的全部归档。每个 ZIP 包含：

```text
manifest.json
sessions/001-<安全标题>-<id>/session.json
sessions/001-<安全标题>-<id>/transcript.md
```

`session.json` 是权威机器记录，`transcript.md` 是可读副本。ZIP 路径会净化并处理重名，批量导出逐条生成。

JSON 会保留附件引用，但不包含附件二进制或后代会话。需要带完整附件的会话树时，请使用 Harness 官方 Session log 导出。

导入只接受本插件的 version 1 ZIP，并始终先预览后写入：

- 已存在的会话 ID 会标记为冲突、禁用并跳过。
- 找不到的工作区会带警告恢复为未分组归档聊天。
- 标签和备注按相同本地限制恢复。
- 导入预览不会渲染原始事件或 Markdown。
- 确认令牌 10 分钟后过期，且只能使用一次。
- 恢复优先使用 Host 的专用恢复入口；没有时改用普通的 `create` / `append` / `locate` 会话写入能力——也就是快照恢复使用的同一条路径。只有两者都不存在的 Host 才返回 `restore-unsupported`，且不写入任何数据。

ZIP 导入与回收站恢复使用不同输入和确认流程。

## 回收站与永久删除

**移至回收站** 会先创建或复用健康保护快照，再提交回收记录；成功提示提供立即 **撤销**。

恢复分为两级：

1. 原会话仍完好时，只移除回收标记。
2. 原件丢失时，通过公开的 `create` / `append` 能力使用已验证快照恢复，并且绝不覆盖已有 ID。

回收站也会列出旧版本创建的快照。恢复保护快照会创建新的归档副本，来源聊天保持不变。每行提供 **永久删除**，标题行右上角提供 **清空回收站**；归档聊天还可以从单条删除图标、项目菜单或标题行“全部删除”确认永久删除。永久删除先记录崩溃恢复意图，再删除该来源的已验证快照，**最后**才删除原会话。在原会话删除前失败会保留完整聊天，之后仍可重试；中断操作会在下次启动时继续。

新版 Host 只公开句柄读取、没有物理会话位置时，浏览、导出以及普通会话的保护快照仍可使用；会话目录空间显示不可用，恢复写入和永久删除会显示 Host 不支持。永久删除的拒绝发生在修改回收记录、保护快照、待处理标记或运行中会话之前。带继承历史的分支会话目前也不会被抓取为快照，因为现有快照格式无法保存继承分界。归档不要求快照；这类会话仍无法移入回收站。

如果 `trash.json` 本身无法读取，回收站会报告不可用，并拒绝所有归档修改（取消归档、标签备注编辑、删除、永久删除），而不是靠猜测继续。归档列表仍可浏览，但会标注为未经核对——无法读取的目录无法证明哪些聊天已被删除。

删除快照附件副本不代表 Harness 全局附件存储会立即删除相同字节；其他会话引用或 Host 的垃圾回收策略仍可能保留它们。

## 空间与保留策略

空间分账会区分：

- 归档和回收会话目录。
- 插件自己的已有快照与当前保护快照。
- 无法统计或降级的项目。
- 重复快照附件字节。

可搜索的详情弹窗不会让长清单挤压主要策略视图。统计结果不会被描述为 Harness 全局可回收附件空间。

**回收站自动清理默认关闭**。可选择 7 天、30 天、90 天或自定义（1–3650 的整数天数）。每条聊天从移入回收站的时间单独计时，到期后自动永久删除，无法恢复；未到期的聊天不会被清空。旧版已保存的保留天数不会自动开启此功能，需要重新选择期限并确认。

首次开启或缩短期限时，确认框会显示已到期聊天的数量和列表，包含没有到期聊天时的未来删除提示。确认有效期为 5 分钟；设置或到期列表发生变化时需重新核对。确认并保存后无需再逐次批准清理。关闭功能或延长期限可直接保存。

DSH 运行时约每分钟检查一次，关闭期间暂停，重新启动且恢复检查完成后补清理。删除前会重新验证当前设置和回收记录；失败的删除保留记录并重试。已经开始永久删除的项目会继续完成，即使此后关闭自动清理。仍可使用回收站中的“永久删除”和“清空回收站”手动清理。

旧版的版本数量、快照年龄与容量设置不再触发快照清理。已有独立快照统一在回收站管理。

## 来源与分支

只读关系视图使用 Harness 持久化 `parentSession` 展示归档或回收聊天的来源、分叉和子代理树。它只保留解释受管理会话所需的活动父子上下文，不会把无关活动聊天发送到浏览器。

搜索会展开折叠分支中的命中路径，项目和状态筛选会保留必要祖先上下文。诊断会报告缺失父节点、循环和委派深度不一致，但不会修改关系。

本版本不认识的会话头——例如更新版 Harness 新增的 origin 取值、缺失的时间戳——只会让那一个节点的细节降级，图的其余部分不受影响。节点上限针对实际展示的关系图，而不是 Harness 存储的会话总数，因此会话历史很多本身不会导致该视图不可用。

## 本地数据与隐私

插件自己的全部状态位于：

```text
$DSH_HOME/plugin-data/archived-chats/
```

目录中可能包含：

- `metadata.json`：标签和备注。
- `trash.json`：回收站记录。
- `legacy-recycle.json`：显示在回收站中的保护快照迁移状态。
- `retention.json`：已保存的保留策略。
- `snapshots/`：已有快照和当前保护快照。
- 尚未完成迁移时的旧版 `pending-deletions.json`。

插件不会上传、云同步或定时后台抓取会话与附件。卸载只移除插件包，并故意保留该目录，以便重新安装后继续恢复同一份状态。

## 常见问题

<details>
<summary><b>归档会删除聊天吗？</b></summary>

不会。DSH 只会把聊天从侧边栏隐藏并保留归档会话记录，会话档案提供管理入口。

</details>

<details>
<summary><b>已有快照去哪里了？</b></summary>

它们现在直接显示在回收站。可读取的快照支持只读预览和恢复为新的归档副本；降级快照只能永久删除。

</details>

<details>
<summary><b>恢复会覆盖来源吗？</b></summary>

不会。保护快照恢复会创建新的归档 ID，普通回收站回退恢复会拒绝已有 ID，两条路径都不会覆盖来源。

</details>

<details>
<summary><b>导入 ZIP 包含已有 ID 时会怎样？</b></summary>

该行会标记为冲突、禁用并跳过。导入绝不会覆盖已有会话。

</details>

<details>
<summary><b>为什么归档列表为空时仍有快照？</b></summary>

恢复回收聊天后可能留下已验证快照。它会作为保护快照显示在回收站，可再次恢复为新归档或永久删除。

</details>

<details>
<summary><b>降级或删除插件数据前应该做什么？</b></summary>

先恢复仍需使用的内容，并备份完整插件数据目录。旧版本可能不识别统一回收站或较新的快照状态。

</details>
