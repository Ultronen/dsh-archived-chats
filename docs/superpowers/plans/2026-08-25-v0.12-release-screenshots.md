# v0.12 Release Screenshots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every stale public preview with a coherent, real-host v0.12 screenshot set and synchronize the product description before the branch is uploaded.

**Architecture:** Capture the actual `feature/0.12.0` browser client through a temporary DeepSeek Harness `0.1.1-rc.2` profile containing only purpose-built synthetic sessions. Accept each screenshot only after inspecting the saved PNG, then update both READMEs and remove superseded assets so npm cannot publish stale images.

**Tech Stack:** DeepSeek Harness Web, `dsh-archived-chats@0.12.0`, Browser Playwright surface, PNG assets, Markdown, Node.js/npm verification.

**Spec:** `docs/superpowers/specs/2026-08-24-storage-retention-lineage-design.md`

## Global Constraints

- Capture only the real plugin UI; generated, mocked, composited, or edited stand-ins are forbidden.
- Use an isolated temporary `DSH_HOME` with synthetic sessions and no credentials, API keys, real conversations, or real workspace paths.
- Capture Chinese, light theme, at `1470x712` unless the archive-entry surface requires its natural `1470x587` crop.
- Keep the product name and settings navigation label `已归档的聊天` / `Archived Chats`.
- Use `恢复快照` / `recovery snapshot` for the user outcome; reserve `保护快照` / `protection snapshot` for low-level integrity and permanent-purge explanations.
- Every settings-page screenshot must show the four v0.12 views: `归档`, `回收站`, `空间与策略`, `来源与分支`.
- Full session IDs may appear only in the dedicated compact-ID/copy treatment or where a technical confirmation genuinely requires one.
- Preserve old screenshots until their replacements have been captured, inspected, and accepted. Git history remains the recovery path after replacement.
- Do not commit, push, tag, publish, or create a release in this plan; leave the verified worktree ready for the user's later upload.
