# dsh-archived-chats 0.9.0 互操作基础设计

## 状态

提案，等待评审。

## 目标

0.9.0 为已归档会话建立可验证、可预览的跨工具交换基础，优先支持 Codex 和 Claude Code。用户可以把外部会话导入 DSH 归档，也可以把归档会话导出为外部工具可读取的格式，并在导入前看到冲突和信息损失。

本版本继续作为 `dsh-archived-chats` 的一部分发布，不创建第二个插件或新的公共 npm 包。

## 非目标

- 不在 0.9.0 一次接入十几个外部工具。
- 不实现持续双向同步、自动覆盖或后台监控外部文件。
- 不承诺所有外部会话都能被目标工具原生 `resume`；无法确认时必须降级为可读迁移或交接恢复。
- 不复制外部工具的附件二进制、凭据、MCP 密钥或本地配置秘密。

## 用户流程

### 外部导入

用户在“已归档的聊天”页面选择“从外部工具导入”，选择来源（Codex 或 Claude Code）和本地文件/目录。插件先只读扫描，展示会话数量、标题、工作区、重复项、格式限制、附件引用和预计转换结果。确认后，冲突会话默认跳过，非冲突会话写入为已归档记录。

### 外部导出

用户选择一个或多个归档会话和目标格式。插件先生成导出预览与完整性报告，再下载目标文件。报告明确区分原生可恢复、可读迁移和交接恢复，并列出被折叠或丢失的事件类型。

## 交换格式

沿用现有带版本 ZIP 的安全结构。互操作清单使用固定的 `format: "dsh-interop"` 和独立的 `formatVersion: 1`，并包含 `source`、`sourceVersion`、`sessionId`、`workspace`、`messages`、`attachments`、`losses` 和 `sha256`。DSH 原始事件仍是权威数据；外部格式只是经过适配的投影。导入不得覆盖已有会话，导出不得修改本地会话或外部源文件。

## 代码边界

- `lib/interop/format.mjs`：交换格式、版本和完整性校验。
- `lib/interop/codex.mjs`：Codex JSONL 读取与导出投影。
- `lib/interop/claude.mjs`：Claude Code JSONL 读取与导出投影。
- `lib/interop/report.mjs`：冲突、损失、附件和恢复能力报告。
- 现有导入确认令牌、事务恢复和元数据限制继续复用。
- UI 只负责选择、预览、确认和下载；格式转换保持为纯函数，便于独立测试。

## 安全与失败处理

外部文件只读访问，路径继续遵守宿主沙箱；扫描和转换不得把原始消息、凭据或路径写入日志。未知行、畸形 JSONL、重复 ID、过大的输入和疑似秘密必须在预览报告中显式失败或告警。任何恢复失败都必须回滚会话、归档索引和本地元数据，不留下半成品。

## 测试要求

- Codex 和 Claude 的最小、多轮、工具调用、异常行和附件引用 fixtures。
- 导入预览的冲突、重复导入、路径限制和有界输入测试。
- 导出报告的无损、降级和不可恢复三类结果测试。
- 交换格式校验、SHA-256、版本拒绝和 round-trip 测试。
- 保持现有全部测试通过，并确认 npm 包不包含本地 `data/` 或外部源文件。

## 发布与兼容性

0.9.0 为向后兼容的 minor 版本。现有 v1 DSH ZIP 导入继续可用；互操作清单使用新版本号，旧宿主能力不足时只提供预览和下载，不执行写入。README、英文 README、架构文档、截图和版本记录必须在实现完成后同步更新。
